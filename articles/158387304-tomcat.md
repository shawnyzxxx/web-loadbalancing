# Tomcat 详解与生产部署实战

## 文章导读
Apache Tomcat 是一个免费开源的 Web 应用服务器，属于轻量级应用服务器，在中小型系统和并发量不高的场景中被广泛使用，也是开发、调试 JSP 程序的首选。本文从 Tomcat 核心概念讲起，覆盖 Java 环境准备、安装启动、目录结构、Systemd 服务化，再到 Nginx 反代整合、负载均衡以及基于 Memcached 的 Session 高可用方案，适合需要在实际生产环境中部署 Java Web 应用的读者。

## 一、Tomcat 核心概述
**核心功能：**

- **Web 服务器**：具备处理 HTML 页面的能力
- **Servlet 容器**：运行 Java Servlet 程序
- **JSP 容器**：解析和运行 Java Server Pages

**版本说明：** 虽然 Tomcat 已更新到 9.0.x / 10.x 版本，但在许多传统企业环境中，8.5.x 和 9.0.x 仍是主流稳定版本。

官网：http://tomcat.apache.org/

## 二、生产环境部署指南

### 2.1 前置依赖：Java 环境安装
Tomcat 基于 Java 运行，必须先安装 JDK/JRE。推荐使用 OpenJDK 1.8 或 11。

```bash
# 安装 Java 环境（CentOS/RHEL）
yum install java-1.8.0-openjdk.x86_64 -y

# 验证版本
java -version

# 查看 Java 安装路径
which java
ls -l /etc/alternatives/jre
```

### 2.2 Tomcat 安装与启动
推荐直接从 Apache 官网下载源码包部署，避免包管理器版本过旧。启动成功后，访问 `http://IP:8080` 即可看到 Tomcat 默认页面。

### 2.3 目录结构详解

| 目录名 | 作用说明 |
|---|---|
| bin | 存放启动（startup.sh）、停止（shutdown.sh）等脚本 |
| conf | 核心配置文件目录（server.xml、web.xml、context.xml） |
| lib | Tomcat 运行所需的 Jar 包库 |
| logs | 日志目录（catalina.out、localhost.log），排错关键 |
| webapps | 应用程序部署目录，相当于 Nginx 的 root 目录 |
| work | JSP 编译后的 Servlet 源文件和字节码文件 |

### 2.4 配置 Systemd 服务管理
为了开机自启并使用 `systemctl` 管理，需要创建服务文件。

**Step 1：创建专用用户**

```bash
useradd -s /sbin/nologin -M tomcat
chown -R tomcat:tomcat /usr/local/tomcat/
```

**Step 2：配置环境变量（/usr/local/tomcat/conf/tomcat.conf）**

```bash
JAVA_HOME=/etc/alternatives/jre
```

**Step 3：创建 Service 文件（/lib/systemd/system/tomcat.service）**

```ini
[Unit]
Description=Tomcat
After=syslog.target network.target

[Service]
Type=forking
EnvironmentFile=/usr/local/tomcat/conf/tomcat.conf
ExecStart=/usr/local/tomcat/bin/startup.sh
ExecStop=/usr/local/tomcat/bin/shutdown.sh
User=tomcat
Group=tomcat

[Install]
WantedBy=multi-user.target
```

**Step 4：重载并启动**

```bash
systemctl daemon-reload
systemctl enable --now tomcat
```

## 三、Nginx + Tomcat 架构整合
在生产环境中，很少让 Tomcat 直接对外服务，通常采用 **Nginx 反向代理 + Tomcat** 的架构（LNMT）：Nginx 处理静态资源、分担并发，Tomcat 专注处理动态 JSP。

### 3.1 场景一：单机反向代理
Nginx 处理静态资源，动态 JSP 请求转发给 Tomcat。

```nginx
server {
    listen 80;
    server_name app.example.com;

    # 静态资源由 Nginx 直接处理
    location / {
        root /data/www;
        index index.html;
    }

    # 动态 JSP 转发给 Tomcat
    location ~* \.jsp$ {
        proxy_pass http://172.25.254.10:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

### 3.2 场景二：负载均衡集群
利用 Nginx 的 `upstream` 模块，将流量分发到多台 Tomcat 服务器。

> **注意 Session 问题：** 默认轮询模式下，用户第二次请求可能被分到另一台 Tomcat，导致登录状态丢失。需配合 `ip_hash` 或后端 Session 共享方案。

```nginx
upstream tomcat_cluster {
    # 基于 Cookie 的会话保持（推荐）
    hash $cookie_JSESSIONID;

    # 或者使用 ip_hash（基于客户端 IP）
    # ip_hash;

    server 172.25.254.10:8080 weight=1;
    server 172.25.254.20:8080 weight=1;
}

server {
    listen 80;
    server_name app.example.com;

    location ~* \.jsp$ {
        proxy_pass http://tomcat_cluster;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

## 四、高阶实战：Tomcat + Memcached 实现 Session 零丢失
要实现真正的高可用（任意一台 Tomcat 宕机不影响用户登录），需要把 Session 数据从 Tomcat 内存中剥离，存储到集中的 Memcached 集群中，这里使用 **MSM（Memcached Session Manager）** 组件。

### 4.1 准备 Jar 包
需要下载 MSM 核心包、序列化包（Kryo）和 Memcached 客户端包，放入所有 Tomcat 的 `lib` 目录下：

- `memcached-session-manager-X.X.X.jar`
- `memcached-session-manager-tc9-X.X.X.jar`（根据 Tomcat 版本选择）
- `spymemcached-X.X.X.jar`
- `kryo-X.X.X.jar`、`kryo-serializers-X.X.X.jar` 等序列化依赖

### 4.2 安装并配置 Memcached

```bash
# 安装 Memcached
dnf install memcached -y

# 修改配置 /etc/sysconfig/memcached
# 确保监听所有接口，允许 Tomcat 连接
OPTIONS="-l 0.0.0.0,::1"
PORT="11211"

# 启动服务
systemctl enable --now memcached
```

### 4.3 配置 Tomcat Context
修改 `/usr/local/tomcat/conf/context.xml`，在 `<Context>` 标签内添加 Manager 配置：

```xml
<Context>
    <!-- 其他配置 -->

    <Manager className="de.javakaffee.web.msm.MemcachedBackupSessionManager"
        memcachedNodes="n1:172.25.254.10:11211,n2:172.25.254.20:11211"
        failoverNodes="n1"
        requestUriIgnorePattern=".*\.(ico|png|gif|jpg|css|js)$"
        transcoderFactoryClass="de.javakaffee.web.msm.serializer.kryo.KryoTranscoderFactory"
    />
</Context>
```

**参数解析：**

- `memcachedNodes`：指定 Memcached 集群节点
- `failoverNodes`：指定故障转移节点（通常指向本机或备用机，防止单点故障）
- `transcoderFactoryClass`：指定使用 Kryo 进行高效序列化

### 4.4 测试验证
1. 部署一个简单的 `test.jsp`，用于显示 Session ID 和当前服务器 IP
2. 访问 Nginx VIP，记录 Session ID
3. 手动停止其中一台 Tomcat 服务
4. 刷新页面，观察 Session ID 是否保持不变，且请求成功跳转到另一台存活节点

测试用 `test.jsp` 示例代码：

```jsp
<%@ page contentType="text/html;charset=UTF-8" %>
<html>
<body>
    <h2>Session Test</h2>
    Session ID: <%= session.getId() %><br/>
    Server IP: <%= request.getLocalAddr() %><br/>
    Time: <%= new java.util.Date() %>
</body>
</html>
```

## 五、小结
Tomcat 的部署可以概括为「**准备 Java 环境 → 安装启动 → 服务化管理 → 反向代理整合 → Session 高可用**」这条主线。生产环境中用 Nginx 承担静态资源与负载均衡，用 Systemd 托管 Tomcat 进程，再通过 Memcached 共享 Session，就能构建出稳定、可扩展的 Java Web 服务集群。掌握目录结构、systemd 配置和 Nginx 整合是落地的关键。
